# Agent Chat

## 当前聊天体验的核心

Aelin 现在的聊天体验，重点不是“像聊天”，而是“把 agent 的真实运行状态带进聊天界面”。

你会看到的核心能力包括：

- 流式输出
- 官方 thread / run 语义
- 工具调用与执行状态
- 附件上下文
- 工作区记忆参与回答

## 当前 UI 真正依赖什么

前端当前依赖的是官方运行态数据，而不是旧时代的兼容字段。

也就是说，执行面板、工具状态和子任务信息应建立在这些数据上：

- `messages`
- `tool call metadata`
- `tasks / subagents`
- `values`

而不是依赖：

- 从回答文本里猜测执行过程
- 自定义 `reply`
- 旧 `tool_trace`
- 旧 `memory_summary`

## session 与 thread 的关系

当前前端把本地会话和官方 thread 尽量保持对齐。

实践上你可以把它理解成：

- 当前会话 = 当前 thread 的产品级表示

这让会话持久化、聊天恢复与执行状态重建都更自然。

## 为什么 Aelin 的聊天更适合持续工作

### 工作区记忆会参与运行时

当前工作区的 `/memory/AGENTS.md` 会被解析并挂载进运行时，所以同一个 workspace 下的后续任务不会总是从零开始。

### 附件能力是主链的一部分

Aelin 不是把附件当成回答后的外挂，而是把它纳入运行时上下文的一部分。

### 右侧执行态不是装饰

在当前设计里，执行态面板的意义不是“让界面更像 agent”，而是把本来就存在的运行态信息真正展示出来。

## Answer-first 仍然成立，但解释方式变了

Aelin 仍然偏向先给可用答案，再给：

- 证据
- 后续建议
- 可继续推进的方向

但与早期版本不同的是，这套体验现在更依赖官方运行时和产品结构，而不是单纯靠 prompt 风格塑造。
