# Device Interaction

## 这项能力来自哪里

Aelin 的设备能力主要来自桌面端，而不是纯 Web 页面本身。

当前 Electron runtime 会提供一层本地桥接能力，使 Aelin 可以在本机环境里调用部分设备相关动作。

## 当前可见的本地能力方向

根据桌面 runtime 与本地插件 API，当前能力主要包括：

- 屏幕捕获
- 打开 URL
- 打开本地路径
- 激活应用
- 在允许条件下执行本地命令

这些能力使 Aelin 不再只是“看网页上的聊天框”，而是开始具备**观察本地环境并触发部分本地动作**的能力。

## 为什么这不是浏览器默认就能做的事

纯浏览器页面没有足够权限直接执行这些能力。

因此你应该把它理解成：

- Web：主要负责聊天与展示
- Desktop：在本机提供更深的设备与系统接入

## 当前使用时要注意什么

### 不是所有平台、所有环境都一样

桌面能力的实际表现依赖于：

- 你是否正在使用 desktop runtime
- 当前操作系统允许什么
- 本地插件桥是否已启动

### 本地执行不是“无边界”

Aelin 当前对工作区、输出目录和设备调用都应维持明确边界。

尤其是涉及文件与命令执行时，产品层应始终清楚回答两个问题：

1. 在哪执行
2. 结果会落到哪里

## 这项能力最适合什么

设备交互最适合这些场景：

- 获取当前屏幕状态
- 让 agent 与本地环境建立最基础的观察能力
- 把回答、文件、命令执行和本机桌面串起来

## 当前阶段的真实定位

当前 Aelin 的设备能力已经很重要，但它仍然属于“有边界的桌面集成”，而不是一个无限制的系统自动化工具。

这也是为什么当前文档更强调：

- 明确边界
- 明确平台差异
- 明确输出路径

而不是夸大它“什么都能控制”。
