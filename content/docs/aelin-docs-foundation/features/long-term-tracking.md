# Long-term Tracking

## 什么叫“长期”

在当前版本的 Aelin 里，“长期”首先意味着：

- 同一主题可以跨多次会话继续推进
- 同一工作区可以持续积累上下文
- 高价值信息能沉淀到文件化记忆

所以长期跟踪的基础，不是一个神秘的后台订阅器，而是：

- thread 的连续性
- workspace 的连续性
- `/memory/AGENTS.md` 的持续沉淀

## 当前已经稳定存在的部分

### 工作区记忆

只要你持续在同一个 workspace 中工作，Aelin 就可以利用之前沉淀下来的上下文继续回答。

### 附件与资料复用

同一主题相关的附件、笔记与结论不需要每次重新解释。

### 产品层可继续构建“跟踪流”

因为运行时和产品边界已经比过去更清晰，所以未来的持续跟踪体验应当构建在显式产品流程上，而不是偷偷塞进聊天主链。

## 当前不应该误解成什么

不要把当前版本理解成：

- 每个问题都会自动创建长期订阅
- 所有对象都会默认被持续监控
- 聊天过程中会默默开启不可见后台任务

这类行为如果存在，应该是：

- 显式的
- 可解释的
- 有边界的

## 什么时候 Aelin 更适合做“长期”工作

下面这些场景，Aelin 会比一次性聊天更有价值：

- 你在持续研究一个项目、公司、主题或资料集
- 你需要把多轮结论沉淀成长期上下文
- 你希望以后回来时，系统还能延续之前的工作状态

## 当前阶段最实用的用法

最稳妥的方式通常是：

1. 为一个主题建立固定 workspace
2. 把资料和附件集中放进这个工作区
3. 让关键结论沉淀进记忆层
4. 在后续会话里沿用同一个 thread 或同一工作区继续推进

这就是当前 Aelin 最真实、最可靠的“长期能力”。
