# Proactive Interaction

## Aelin 对“主动”的理解

主动交互并不等于“系统擅自替你做决定”。

在 Aelin 里，更合理的主动能力应该具备三个前提：

- 明确的触发条件
- 明确的作用范围
- 明确的可解释性

## 为什么当前版本不会把主动能力塞进聊天主链

当前 Aelin 的主链正在向更清晰的 DeepAgents-native 结构收敛。

这意味着：

- 聊天主链负责 thread / run / tools / memory
- 产品层负责配置、设备、附件与后续体验

如果把大量隐式“主动逻辑”硬塞进聊天主链，就会重新回到过去那种：

- 状态难以解释
- 上下文来源不清楚
- 功能边界越来越糊的系统

## 当前最合理的主动路径

主动体验更适合建立在显式产品流程上，例如：

- 某个状态变化达到阈值后提醒用户
- 某个工作流完成后触发下一步建议
- 某个长期主题出现变化时发出可解释的更新

这里的关键词是：

- **显式**
- **可追踪**
- **可关闭**

## 当前文档为什么要这样描述

因为当前 Aelin 的重点是先把这些基础打稳：

- 官方 thread / run 流式链路
- 文件化记忆
- 工具与工作区边界
- 桌面与产品能力的清晰接入

在这个基础之上，主动交互才会是“产品能力”，而不是“不可见的 prompt 魔法”。

## 如果你在设计自己的主动流

最推荐的思路是：

1. 先定义清晰触发条件
2. 再决定是否需要后台执行
3. 最后把结果落到用户可以理解的产品界面里

这样做出来的主动体验，才会和当前 Aelin 的整体方向一致。
