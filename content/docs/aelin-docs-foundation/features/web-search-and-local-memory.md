# Web Search + Local Memory

## 先说结论

Aelin 不是“每次都上网”，也不是“只靠历史记忆”。

它更像是把两类能力拆开使用：

- **Web Search** 负责处理时效性与外部证据
- **Local Memory** 负责维持工作区连续性

## Web Search 解决什么问题

外部搜索适合回答这些问题：

- 信息可能已经变化
- 需要最新证据
- 需要链接、引用或来源核对
- 当前工作区里本来就没有这份信息

比如：

- 最新版本
- 产品更新
- 新闻与公告
- 第三方页面内容

## Local Memory 解决什么问题

本地记忆适合回答这些问题：

- 你之前已经在这个工作区里反复研究过
- 这个任务需要继承长期背景
- 你希望把高价值结论持续沉淀下来

当前主链的记忆锚点是：

- `/memory/AGENTS.md`

这意味着 Aelin 的记忆不是一个看不见的“魔法脑袋”，而是明确落在工作区文件里的。

## 为什么要把两者分开

如果只有搜索，没有记忆，就会出现：

- 每次都重新解释背景
- 同一主题无法连续推进

如果只有记忆，没有搜索，就会出现：

- 最新信息缺失
- 外部证据不足
- 难以处理变化很快的对象

因此，当前 Aelin 更像是在做一件事：

> 用文件化工作区记忆保持连续性，再用搜索补足时效性。

## 这和“隐藏上下文拼装”有什么区别

区别非常大。

当前设计下：

- 记忆来源清楚
- 搜索是显式工具能力
- 用户与开发者都更容易判断答案到底来自哪里

这比把各种摘要、缓存和临时上下文塞进一条不可见 prompt 链路里更可维护。

## 实际使用建议

如果你在同一个主题上连续工作，最好的方式通常是：

1. 固定使用同一个 workspace
2. 让关键结论进入工作区记忆
3. 对确实需要最新信息的部分再用外部搜索补齐

这样 Aelin 的表现会比“每次新开一个完全无上下文的对话”稳定得多。
