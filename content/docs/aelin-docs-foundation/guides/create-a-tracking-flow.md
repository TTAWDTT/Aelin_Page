# Create a Tracking Flow

这份指南不把“tracking”写成一个神秘按钮，而是告诉你：在当前 Aelin 里，怎样组织一个**真实可持续的主题工作流**。

## 1. 先定义一个清晰主题

最好的 tracking flow 往往都有明确对象，例如：

- 一个项目
- 一家公司
- 一组文档
- 一个功能方向
- 一批持续更新的资料

不要从“我要长期跟踪一切”开始，而要从“我要持续围绕这个主题工作”开始。

## 2. 建一个专用 workspace

同一主题最好固定在同一个 workspace 中。

这样做的意义是：

- 附件上下文集中
- 记忆沉淀集中
- 后续会话的连续性更强

## 3. 先完成第一次高质量对话

第一次对话建议包含：

- 目标是什么
- 当前已知资料有哪些
- 哪些内容需要外部搜索验证
- 你希望后续持续关注什么

这一步的输出，决定后面是否真的能形成长期闭环。

## 4. 让关键结论沉淀下来

Aelin 当前长期能力的基础，是工作区级的文件化记忆。

所以真正重要的不是“模型一时记住了什么”，而是：

- 哪些信息值得进入长期记忆
- 哪些信息只是这轮对话的临时上下文

## 5. 把资料和附件放进同一工作区

如果主题依赖固定资料，建议把这些内容也纳入同一工作区：

- 文档
- PDF
- 附件
- 结构化笔记

这样后续 run 才能更稳定地复用它们。

## 6. 在后续会话里复用同一主题

当你回来继续做这件事时，优先：

- 使用同一个 workspace
- 在可能的情况下沿用同一 thread 或相关会话链路

这样 Aelin 才能把：

- 当前提问
- 历史记忆
- 旧附件
- 新搜索结果

组合成真正的连续工作流。

## 7. 如果你要做“主动”或“定期”流程

在当前架构里，更推荐把这类能力做成显式产品流程，而不是让聊天主链偷偷承担：

- 定期检查
- 条件触发
- 后台提醒

这样你才能清楚知道：

- 是什么触发了它
- 它在哪运行
- 结果写到了哪里

## 一个最实用的判断标准

如果这个 flow 能同时回答下面三个问题，它通常就是健康的：

1. 主题是不是清晰的
2. 上下文是不是落在固定 workspace 里
3. 高价值结论是不是能进入长期记忆
